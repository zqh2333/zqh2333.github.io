# 云视听自建服务：部署现状与入口基线

## 日期
2026-11-10

## 何时用
排查「云视听 / 电视端播不了 / 设备未授权 / 转圈 / 拿不到播放地址」，或需要确认这套服务到底装到哪一步时。

## 服务定位
自建腾讯视频（云视听极光）解析中转：服务器持有腾讯登录态 Cookie，电视端 APK 指向本机，由服务端代取播放地址。**不是**破解，本质是把网页版登录态转成 TV 端可播流。

## 拓扑

```text
电视 APK ──https://qqvideo.example.com:2333/<secret>/...──▶ Lucky :2333
                                                              └─▶ https://<LAN-8>:18081
                                                                   （qqvideo-resolver, TLS）
后台浏览器 ──https://qqvideo.example.com:2333/admin──▶ 同上
```

| 项 | 值 |
|---|---|
| 后端主机 | `<LAN-8>`（宝塔 docker 宿主机） |
| 程序目录 | `/opt/qqvideo-relay/` |
| 监听 | `0.0.0.0:18081`（HTTPS）、Chrome CDP `127.0.0.1:9333` |
| 运行用户 | `resolver`（uid 999） |
| 外网入口 | `https://qqvideo.example.com:2333`（Lucky 反代，`:2333` 必须带） |
| DNS | `qqvideo.example.com → <PUBLIC-IP>`，灰云（proxied=false） |
| 证书 | 复用 Lucky 的 `*.example.com` Let's Encrypt 泛域名，无需单独签发 |
| 后台 | `https://qqvideo.example.com:2333/admin`，账号 `admin`，密码见 `config.json` 的 pbkdf2 哈希（不可逆） |
| secret | `config.json` 的 `secret` 字段，APK 地址 `https://qqvideo.example.com:2333/<secret>` |
| 导航条目 | Sun-Panel id 33「云视听」，sort 23，图标手绘（电视+播放三角，`#3B82F6→#22D3EE`） |
| 教程与工具归档 | `~/qqvideo-tutorial/`（`tutorial_pack.zip` / `apk_tool.zip` / 解压目录） |

## 三个 systemd 单元

```bash
systemctl status qqvideo-resolver qqvideo-chrome qqvideo-keepalive
```

- `qqvideo-resolver` — 主服务，18081，TLS
- `qqvideo-chrome` — headless Chrome，给 resolver 走腾讯网页接口
- `qqvideo-keepalive` — 每约 9 分钟刷新 Cookie

## 健康判据（按顺序）

```bash
# 1. 服务
systemctl is-active qqvideo-resolver qqvideo-chrome qqvideo-keepalive

# 2. 后端直连
curl -skS -o /dev/null -w '%{http_code}\n' https://<LAN-8>:18081/admin/login   # 200

# 3. 外网严格 TLS（禁 -k）
curl -sS -o /dev/null -w 'http=%{http_code} verify=%{ssl_verify_result}\n' \
  https://qqvideo.example.com:2333/admin/login      # http=200 verify=0

# 4. 应用层
curl -sS -o /dev/null -w '%{http_code}\n' https://qqvideo.example.com:2333/<secret>/getvinfo  # 200
```

## 故障分层对照

| 现象 | 根因 | 位置 |
|---|---|---|
| 电视一直转圈 / 「设备未授权」 | 设备没在后台授权 | `devices.json` 里 `authorized=false` |
| 能连上但取不到播放地址 | **Cookie 池为空**（从未扫码） | `cookies_pool.json` 不存在，日志 `cookies=0` |
| 保活日志反复 `no vusession` | Chrome 没有登录态 | `cookies.json` 缺失，先扫码 |
| 后台打不开 | 走了 `:443` 而非 `:2333`，或 Lucky 规则缺失 | `https://dh.example.com/` 会撞 iStoreOS 自签证书 |
| 公网直连 18081 不通 | 正常，18081 未做公网映射 | 一律走 Lucky `:2333` |

## 关键坑

1. **教程写的 `:18081` 在本环境外网不通**，APK 必须填 `:2333` 的 Lucky 地址，否则直接连不上。
2. **版本一致性可校验**：`/opt/qqvideo-relay/resolver.py` 的 sha256 与教程包内 `服务端/resolver.py` 完全一致（本次核对 v3，2095 行）。升级前先比 hash。
3. **`cookies=0` 是硬阻塞**，不是配置问题 —— 必须人工扫码 `/admin/qr`，任何自动化都替代不了。
4. `devices.json` 里出现 `ip:127.0.0.1` / `ip:<LAN-3>` 是本地探测留下的，不代表电视已连接。
5. `admin_allow_cidrs` 为空 = 后台对全网开放；要收紧就填内网段 + 家庭出口 IP。
6. UFW 当前 `inactive`（教程 install.sh 第 7 步会配），不影响访问但少了层防护；如启用务必先放行 18081 和 SSH。

## APK 改包：绕过「没有找到作者的原始地址」

### 报错根因

作者工具 `云视听改包工具.exe`（PyInstaller 打包）定位方式是 **匹配作者写死的完整原始地址字符串**，所以只认 `2026-02-09` 那一版打印包。任何其它版本都会报：

> 这个 APK 已经改过地址了，请用 2026-02-09.apk 原始包

判断手上 APK 是不是那一版：看 zip 内 `classes3.dex` 的修改时间戳 —— 目标版是 `2026-02-09 15:50`（`classes5.dex` 同为该时间）。

### 实际改的两个点（从 `云视听test-example.apk` 反编译确认）

| dex | smali 文件 | 原始常量 |
|---|---|---|
| `classes3.dex` | `com/tencent/qqlive/tvkplayer/vinfo/vod/b.smali` | `https://<server>/getvinfo` |
| `classes5.dex` | `com/tencent/qqlivetv/windowplayer/module/business/defauth/DefAuthRequest.smali` | `https://<server>/i-tvbin/app/playable?` |

**腾讯官方 `https://vv.video.qq.com/getvinfo` 和 `https://bkvv.video.qq.com/getvinfo` 必须保留**（主/备链路），改了反而难回退。

### 版本无关改包器

`~/.hermes/scripts/patch_qqvideo_apk.py` —— 不匹配完整 URL，按 **接口路径后缀**（`/getvinfo`、`/i-tvbin/app/playable`）定位，因此不挑 APK 版本。

```bash
# 先探测能不能改（只读）
python3 ~/.hermes/scripts/patch_qqvideo_apk.py --scan-only --apk 云视听极光.apk

# 真改包
python3 ~/.hermes/scripts/patch_qqvideo_apk.py \
  --apk 云视听极光.apk \
  --server https://qqvideo.example.com:2333/<SECRET> \
  --out 云视听极光.patched.apk
```

流程：解 zip → baksmali 反编译命中的 dex → 正则替换 `const-string` → smali 回编译 → 按原 ZipInfo 重新打包 → `zipalign -p 4` → `apksigner` 用 `testkey.jks` 重签 → `apksigner verify`。

**工具链（本机已装）**：`default-jdk-headless`、`apksigner`、`zipalign`；baksmali/smali 用工具包自带 jar。

**签名密钥**：`~/qqvideo-tutorial/apk_tool/云视听改包工具/tools/testkey.jks`，storepass=`android`，alias=`testkey`，证书指纹 SHA-256 `a40da80a…71bf5dc`（与作者工具同一把 AOSP testkey）。

### 交付记录（2026-11-10）

- 输入：`云视听test-example.apk`（30.3 MB，地址为占位符 `test.example:8443`）
- 输出：`~/qqvideo-tutorial/云视听极光.patched.apk`（28.8 MB）
- MD5 `<HASH>`
- `apksigner verify` → v1/v2/v3 全通过，签名者 CN=Android（AOSP testkey）
- 包内地址已指向 `https://qqvideo.example.com:2333/<SECRET>/getvinfo` 与 `.../i-tvbin/app/playable?`

### Windows 桌面通用版（2026-11-10 交付）

给非 Linux 环境用的双击版：**换域名 / 换 secret / 整串换** 三种模式，内置 Java，不挑 APK 版本。

| 项 | 值 |
|---|---|
| 产物 | `~/qqvideo-tutorial/改包工具通用版/云视听改包工具.exe`（34 MB，PE32+ GUI x86-64） |
| 打包 | `云视听改包工具-通用版.zip`（含使用说明） |
| MD5 | `<HASH>` |
| 源码 | `~/.hermes/tools/qqvideo-patcher-win/`（`main.py` GUI + `wpatch.py` 引擎 + `tools/` + `runtime/jre`） |
| 重打 | `bash ~/.hermes/tools/qqvideo-patcher-win/build.sh`（Linux + wine 交叉编译，约 5 分钟） |

**设计要点**

- 定位逻辑与 Linux 版一致：按 `/getvinfo`、`/i-tvbin/app/playable` 接口后缀找，不依赖作者写死的完整 URL
- `只换域名` 不带端口 → 继承原端口（`:2333`）；secret 原样保留
- 腾讯官方 `vv.video.qq.com` / `bkvv.video.qq.com` 始终保留
- 内嵌作者原包的 `runtime/jre`（Windows x64 JRE 17.0.18，jlink 裁剪），客户端无需装 Java
- 签名仍用同一把 AOSP testkey，输出 v1+v2+v3

**验证证据（在 Windows 环境实测，非仅编译通过）**

- 引擎级：`secret` 模式改包 → 域名保持 `qqvideo.example.com:2333`，v1/v2/v3 验签通过
- exe 级自测（`QQPATCH_AUTOTEST` 环境变量入口）：`OK|2|...`，替换 2 处并正常退出
- 产物核验：`https://exetest.example.org:2333/<22位secret>/getvinfo`，端口继承成功、腾讯 2 条未动、secret 长度 22
- 子进程命令行确认跑在 `C:\users\...\Temp\_MEI######\tools\smali-fat.jar` → 内嵌资源解析正确
- 界面在 Xvfb 下截图核验：无乱码、无豆腐块、无控件截断

**坑（重打时注意）**

- tkinter 字号必须整数，`9.5` 直接抛 `TclError`
- `--add-data` 的源必须写绝对路径，否则 `--specpath` 会让它去 `build/` 下找
- `--windowed` 下 `sys.stdout` 是 None，日志只能写 GUI 控件
- 子进程必须加 `CREATE_NO_WINDOW`（`creationflags=0x08000000`），否则每个 java 调用弹黑窗
- Windows Defender 常误报 PyInstaller 单文件产物，使用说明里已提示加白名单

完整交叉编译流程见技能 `windows-exe-cross-build-wine`。

### 装电视

1. **先卸载电视上的官方/旧版 App**（签名不同，覆盖装会报「应用未安装」）
2. 允许「未知来源应用」
3. 装 `云视听极光.apk`，打开后播放任意视频一次触发设备注册
4. 回后台批准设备，再设默认清晰度

### 端到端判据

```bash
curl -sS "https://qqvideo.example.com:2333/<SECRET>/getvinfo"
# 打通时应答（85 字节），设备未批准时内容是：
#   <root><em>61</em><exem>1</exem><msg>设备未授权，请在后台批准</msg></root>
```

**看到「设备未授权」= 链路完全正常**，只剩后台授权这一步；若 timeout/404 才是链路问题。

失败/报错自动修复（用户硬规则，全范围）

规则（2026-07-18 强化）

不仅是脚本——所有问题都适用：

只要出现失败、报错、异常、不可用、配置不兼容、服务挂掉、cron 失败、认证失效、网络/设备异常等： 1. 自动排查并修复到可验证通过 2. 不要只诊断汇报、停在“建议你手动…” 3. 不要等用户催促后再修 4. 修完后实跑验证（exit 0 / 功能可用 / 健康检查通过） 5. 结论主动沉淀到知识库（~/.hermes/knowledge-base/）

适用范围（全链路）

  • Hermes cron / 签到 / 同步 / 菜单脚本
  • CPA 配置、桥接、auth、proxy、docker/systemd
  • 家庭实验室设备巡检可修复项（SSH、服务、磁盘告警处置等）
  • 依赖缺失、权限、端口、跳板连通
  • 本会话内工具失败导致的任务阻塞
  • 其他非脚本类配置/服务/网络问题

工作方式

复现 → 定位根因 → 直接修复 → 验证 → 知识库沉淀

例外（仍要说明，但先尽量找替代路径）

  • 缺用户专有凭据/密钥且无备份无法恢复
  • 明确需人工决策的破坏性操作（大规模删数据等）
  • 上游第三方站点本身不可用且无本地替代

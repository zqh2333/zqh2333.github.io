CPA 上游「烁」403 假页面 = Cloudflare UA 封禁（error 1010）

日期：2026-10-11 分类：incidents 状态：已修复并端到端验证

背景 / 现象

  • 症状：CPA 里 suo:glm-5.3、suo:glm-5.3-flash 一律不可用。Hermes 报 ⚠️ The model provider failed after retries；日志里是 PermissionDeniedError / HTTP 403 — 系统终端 - 异常状态诊断。
  • 403 的响应体不是 JSON API 错误，而是一个伪装 HTML 页 （<title>系统终端 - 异常状态诊断</title>、TERMINAL COGNITIVE REPORT // PORT 404）。
  • 计费库统计：provider 烁（上游 https://elysiver.h-e.top/v1） 自 2026-09-09 上线到 10-11 共 81 次请求，81 次全部失败、0 次成功； 覆盖 grok-4.6(43)、deepseek-v4-pro-0813(20)、deepseek-v4-flash-0731(7)、 glm-5.3(6)、glm-5.3-flash(5) —— 连不用工具的模型也全挂。

排查过程（排除项）

假设 证据 结论
限制工具调用 81/81 全挂，含无工具模型；本地计费插件 routes 表为空、api_keys 无模型限制 排除
缺价格被计费拦截 早期确有 model_price_error 模型 suo:glm-5.3-flash 尚未定价，但价格已补齐（suo:glm-5.3 1.4/4.4、-flash 0.15/0.5） 排除（已修）
key 失效 3 条 key 实际只有 2 把（1 条重复），但换任何 key 都一样 非主因
上游整站拒绝 403 响应头 server=cloudflare 命中

根因

Cloudflare error 1010：站点 elysiver.h-e.top（CF 前置）把 Python/脚本类 User-Agent 拉黑了。CPA 默认用 OpenAI/Python SDK 的 UA 出站， 所以每个请求在 CF 边缘就被 403 掉，根本到不了模型层。 这也解释了为什么响应是 HTML 伪装页而不是 API JSON 错误。

修复

给该 provider 单独挂 codex 指纹请求头（不碰全局 codex-fingerprint， 不影响其他 provider）：

openai-compatibility:
  - name: 烁
    base-url: https://elysiver.h-e.top/v1
    headers:                                    # ← 新增，仅此 provider
      User-Agent: "codex_cli_rs/0.114.0 (Mac OS 14.2.0; x86_64) vscode/1.111.0"
      originator: "codex_cli_rs"
      version: "0.114.0"

要点： - CPA 的 openai-compatibility 条目支持 headers: 自定义出站头 （值以 $ 开头可动态复制下游客户端同名头）。这是 per-provider 的。 - 顶层 codex-header-defaults 只对 OAuth/文件型 Codex 生效， 对 openai-compatibility 条目无效，别指望它。 - CPA 热加载 config.yaml，改完不需要重启容器。 - 备份：/root/CLIProxyAPI/config.yaml.bak_before_suo_codexua_<时间戳>

验证方式与实际结果

受控对照（直打上游，一次一发）：

出站 UA 结果
默认 python-urllib HTTP 403，server=cloudflare，error code: 1010
codex_cli_rs/0.114.0 … HTTP 200 ✅ 真实补全
Chrome UA HTTP 200 ✅

改配置后经 CPA 端到端复测：

请求 结果
suo:glm-5.3 HTTP 200
suo:glm-5.3-flash HTTP 200
suo:glm-5.3 + tools + tool_choice:auto HTTP 200，finish_reason=tool_calls，正确返回 get_weather({"city":"Beijing"}) ✅

可复用教训

  1. 403 + 自定义 HTML 页（而非 JSON） ⇒ 先怀疑边缘/WAF，不要在后端模型配置里找原因。
  2. 响应头里的 server: cloudflare + error code: 1010 就是「UA 被封」的铁证。
  3. 公共 openai-compat 上游默认用 OpenAI/Python UA；遇到 CF UA 封禁时， 只给该 provider 加 headers 是最小改动，比全局改 UA 安全得多。
  4. 不要拿「工具调用被限制」解释一个所有模型都挂的上游故障——用「有没有成功过」一刀切开。

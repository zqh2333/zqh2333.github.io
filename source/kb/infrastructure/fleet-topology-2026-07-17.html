一句话结构

  • 出口主路由：ROS（MikroTik CHR） —— PPPoE 拨号、DHCP、NAT、大部分终端默认网关
  • 旁路/业务辅助：OpenWrt iStoreOS —— IPTV 网段、Clash 代理、被 PVE 主机当作默认网关
  • 计算底座：PVE —— 几乎所有业务机都是其上的 VM/LXC
  • DNS：AdGuard Home（） —— DHCP 下发的主 DNS
  • 应用层：宝塔（CPA 模型代理）、Hermes、NAS、HA

路由与流量路径

终端上网（主流）

终端 → 默认网关 <LAN-2>(ROS) → pppoe-out1 → 公网

证据： - Hermes / NAS / AdGuard / 宝塔：default via <LAN-2> - ROS DHCP network：gateway=<LAN-2> dns-server=<LAN-6> - ROS main 默认路由：gateway=pppoe-out1（公网地址动态）

PVE 主机自身

PVE → 默认网关 <LAN-3>(OpenWrt) → 再经 ROS 出口

这是与业务终端不同的路径：PVE 管理流量走 OpenWrt，可能用于代理表/策略分流（ROS 上有 routing-table=proxy gateway=<LAN-3>）。

拓扑结论

  1. 核心交换/二层：业务机都在 <LAN-0>/24，PVE vmbr0 是管理网桥，ROS/OpenWrt/业务 VM 同网段互通。
  2. 三层出口权威：ROS —— 真正的 WAN（PPPoE）与 DHCP 网关权威。
  3. OpenWrt 不是主网关（对终端），而是 旁路增强节点（IPTV、Clash、电信认证、给 PVE/策略路由用）。
  4. DNS 权威：AdGuard —— 与 ROS DHCP 配置一致。
  5. 几乎全家桶虚拟化：路由、旁路、DNS、NAS、HA、宝塔、Hermes 都跑在同一台 PVE 上 → 单点是 PVE 硬件/存储，不是某一个应用容器。
  6. 双路径设计：终端走 ROS；PVE 主机走 OpenWrt。排障时不要假设“全网同一默认网关”。

建议（非阻断）

  1. NAS 根分区 70%：安排清理/扩容。
  2. PVE 内存 44G/62G：VM 密度高，避免再无节制加内存规格。
  3. HA SSH 视角受限：若要巡检宿主机网卡，需走 HAOS 主机 SSH/控制台，而不是仅 core-ssh 插件。
  4. 文档化双网关：在变更 OpenWrt/ROS 时同步检查 PVE 的 gateway <LAN-3> 是否仍符合预期。
  5. CPA CPU warn：长会话时正常；privacyfilter 保持关闭。

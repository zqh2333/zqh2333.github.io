青龙 API 调用契约（v2 后端实测）

分类：runbooks 日期：2026-10-31

背景

给青龙写自动化脚本（触发任务、批量改环境变量、读日志）时，凭猜测写 HTTP 方法/body 会连续踩坑： 同一个 /api/crons/run 端点，POST 返回 404（路由未匹配，回的是 HTML 错误页）， PUT + {"ids":[123]} 返回 400 Validation failed（提示 "value" must be an array）， 两种都看起来像"服务不可用"，实际只是契约不对。同理环境变量批量新建逐条提交必然 400。

结论（可直接照抄的契约）

用途 方法 路径 body
登录 POST /api/user/login {"username":"<user>","password":"<pass>"} → data.token
运行任务 PUT /api/crons/run 裸数组 [123]（不是 {"ids":[123]}，不是 {"value":[123]}）
读最新日志 GET /api/crons/<id>/log 无 → data 是整篇日志字符串，不是列表
任务详情 GET /api/crons/<id> 无 → data 是 dict（command/schedule/isDisabled…）
环境变量列表 GET /api/envs?searchValue= 无
环境变量批量新建 POST /api/envs 数组，每项 {name,value,remarks}；逐条字符串 value 会 400
环境变量更新 PUT /api/envs 对象，必须带 id
环境变量删除 DELETE /api/envs id 数组
任务列表 GET /api/crons?searchValue= 无 → data 是 dict（data[] 才是条目）

鉴权：所有请求加 Authorization: Bearer <token>；Content-Type: application/json。

验证方式

  • 触发后用日志全文做结束判定：轮询 /api/crons/<id>/log，日志全文发生变化且含 ## 执行结束 标记 → 本轮结束。 注意不能靠"日志长度变大"判断，新日志会先变短（新一轮从 ## 开始执行 写起）。
  • 触发成功返回 {"code":200}；失败会给出 __http + __body，照上表对号入座。

实际结果

按上表改写后：PUT /api/crons/run + [123] → code 200，任务立即执行并在 5 秒内跑完（当日任务已全部完成时）， 日志轮询正确捕获 ## 执行结束。

坑

坑 正解
POST /api/crons/run 404，HTML 错误页；必须 PUT
{"ids":[…]} 传 id 列表 400 "value" must be an array；要裸数组
把 /log 的 data 当列表遍历 它是字符串；要日志列表用别的手段
逐条 POST /api/envs 400；一次提交整个数组
用"日志变长"判结束 新日志先变短；用 ## 执行结束 标记
终端里跑 docker exec … grep/tail 只回 1 行 命令输出重定向到 /tmp/x，再用脚本读文件解析
远端嵌套引号被双层 shell 吃掉 shlex.quote 单层引号 + 单引号包 sh -c
非登录 shell 里 task 命令 127 用 bash -lc 或先 source /ql/shell/env.sh

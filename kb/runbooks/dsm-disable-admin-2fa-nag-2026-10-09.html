去掉 DSM 登录时的「管理员帐户安全性」2FA 弹窗（2026-10-09）

现象

每次登录 DSM 网页，右下角弹出一个白色通知卡：

  • 橙色感叹号图标，标题（蓝色）「管理员帐户安全性」
  • 正文：默认帐户"admin"容易遭到暴力破解…您可以通过双重验证(2FA)来保护您的帐户， 不过我们建议您停用"admin"帐户。
  • 只有一个按钮「启用 2FA」+ 右上角 X

点 X 只关当前这次，下次登录照弹。

关键认知：这不是真的 2FA 验证

它是安全告警（advisory），不是验证码挑战。SSH 层根本没有 2FA：

/etc/ssh/sshd_config:  ChallengeResponseAuthentication no
/etc/pam.d/sshd:       无任何 OTP 模块
/var/log/auth.log:     无 OTP/challenge 记录

所以不要去关 SSH 的 2FA（没有可关的），也不要真的去开 2FA（那会变成每次登录 真的要输验证码，与诉求相反）。

机制（逆向结果）

环节 落点
前端模块 /usr/syno/synoman/webman/modules/DisableAdminNotification/
前端 JS DisableAdminNotification.js（Vue，autoLaunch:true, hidden:true）
后端 API SYNO.Core.DisableAdmin（/usr/syno/synoman/webapi/lib/SYNO.Core.DisableAdmin.so）
API 方法 get 和 ignore
配置存储 /etc/synoinfo.conf（经 libsynoserviceconf.so.7）
开关键 hide_disable_admin_notification="yes"
相关键 notify_disable_admin、reset_admin

JS 判定逻辑（反混淆后）：

canOpen(){
  let n = SYNO.SDS.App.DisableAdminNotification.notified;
  return !(!_S("is_admin") || !0===n || (…, this.disableAdminInfoLoad(), 1))
}
disableAdminInfoLoad(){
  synowebapi.request({api:"SYNO.Core.DisableAdmin", method:"get", version:1})
    .then(n => { if (n.notify_disable_admin) /* 弹通知 */ })
}

即：是管理员 且 get 返回 notify_disable_admin=true → 弹。

get 的服务端判定（从 .so 符号推出）： SYNOUserTwoFactorStatusGet（该账户没开 2FA）+ SYNOUserCheckExpired（账户启用中） + hide_disable_admin_notification 未设 → true。

★ 两个误导性极强的坑

  1. 文案里有 info_ignore = "不再显示"，但组件根本没实现它。 [disable_admin_notification] 段落里确实有这个字符串，然而 disable-admin-tray.vue 渲染时写死 has-cancel-btn:!1（没有取消按钮）， 只绑定了 confirm（启用 2FA）和 on-close（X，纯关闭）。 "不再显示" 是遗留未用字符串 —— 别以为点 X 或找那个选项就行。
  2. strings 在 DSM 上不存在。.so 提字符串要用 grep -aoE "[ -~]{4,}" file.so。

修法（官方 API，一步）

DSM 自带本地 webapi 调用器 /usr/syno/bin/synowebapi，以 SYSTEM_ADMIN 身份执行， 不需要密码、不需要 _sid：

# 0) 先备份（配置改动铁律）
cp -a /etc/synoinfo.conf /etc/synoinfo.conf.bak-$(date +%Y%m%d-%H%M%S)

# 1) 看现状
/usr/syno/bin/synowebapi --exec api=SYNO.Core.DisableAdmin method=get version=1
#   → {"data":{"notify_disable_admin":true}, "success":true}

# 2) 关掉（就是前端那个没做按钮的 Ignore）
/usr/syno/bin/synowebapi --exec api=SYNO.Core.DisableAdmin method=ignore version=1
#   → {"success":true, "httpd_restart":false}

验证（闭环）

grep -n hide_disable_admin_notification /etc/synoinfo.conf
#   → 2706:hide_disable_admin_notification="yes"

/usr/syno/bin/synowebapi --exec api=SYNO.Core.DisableAdmin method=get version=1
#   → {"data":{"notify_disable_admin":false}, ...}   ← 条件已解除

这条 get 就是浏览器登录时走的同一条代码路径，返回 false 即代表不会再弹。 httpd_restart:false → 无需重启任何服务，下次登录直接生效。

撤销

/usr/syno/bin/synosetkeyvalue /etc/synoinfo.conf hide_disable_admin_notification no
# 或直接删掉该行；也可从 /etc/synoinfo.conf.bak-* 恢复

⚠️ 安全说明（只是隐藏告警，没改变安全态势）

  • admin 帐户仍然启用、仍然没开 2FA —— 弹窗说的风险原样存在。
  • 实测：administrators 组只有 admin 一个成员 → 不能直接停用 admin， 否则会把自己锁在门外。
  • 要真正加固，正确顺序是： 1. 新建/指定另一个管理员（如 yiting）并加入 administrators 组 2. 用新管理员登录验证权限 3. 再停用 admin 4. （可选）给管理员账户开 2FA
  • 本操作没有做上述任何一步，只是把 nag 关掉。

持久性

写在 /etc/synoinfo.conf，重启/升级一般保留。 但 DSM 大版本升级可能重置该文件 —— 若某天弹窗复活，重跑一次 ignore 即可。

## 关键坑

### 1. 青龙 API token 已过期 → 只能改库 + 重启
`/api/crons` 直接带 `auth.json` 里的 `token` 会返回 `401 invalid signature`；
`config/token.json` 里的 `value` 是 36 位 UUID，带上返回 `401 jwt malformed`
（面板要求 HS384 JWT，`auth.json.tokens` 里存的旧 JWT 已 exp 过期）。
**没有明文密码就无法登录 API**。可行路径：直接改 SQLite `Crontabs` 表，然后
`docker restart qinglong`（调度器在启动时重读，实测 10 秒面板恢复，
重启后 `crontab.list` 立即出现新 command）。改库前先确认容器内没有任务在跑。

### 2. 通知必须走 `task` 包装器，直接 `python3 dx.py` 不会推送
青龙的推送是 `task` 预加载（`/ql/shell/preload/__ql_notify__.py`）接管的，
`notify.py` 本身只认 `SKIP_PUSH_TITLE`，账号里也没有任何 `PUSH_*`/`WEBHOOK` 类环境变量。
所以：
- `docker exec ... python3 dx.py` → 只打印，**不推送**；
- `docker exec ... task dx.py` → 末尾「企业微信推送成功！」✅
验证任务时一定要用 `task` 形态，否则会误判"推送没配"。

### 3. 缓存 schema 被新版接管
`chinaTelecom_cache.json` 原本是 JS 版写的，Python 版读它会走 `token` 复用分支
（`token` + `userId` 齐全就直接用，`map/clientXML` 报"过期"才重登）。
实跑后缓存被覆写为 Python 结构（每账号 3 字段），旧文件已备份可回滚。

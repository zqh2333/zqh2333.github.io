pdd-clone 接真实拼多多：状态从 SSR rawData 取，领取才用浏览器

  • 日期：2026-10-17（含 14:5x 修正）
  • 主机：宝塔 / 容器 pdd-clone / 端口 8899
  • 结论：核验 744ms 返回真实状态；领取仍走真实浏览器点击。

关键修正：数据不是 XHR，是服务端渲染

第一版方案监听 Playwright 的 response 事件等 /api/aurum/check_in/task/query， 在真实账号上永远等不到——活动页首屏数据是 SSR 直接写进 HTML 的：

window.rawData.store.signCouponStore.signCouponInfo
  progressInfo.currentSignNum / totalSignNum   → 已打卡 / 需打卡
  couponInfo.canClick / hasReceived            → 能否领 / 是否已领
  couponInfo.buttonInfoList[].text             → "明日再来" 等按钮文案
  signButtonInfo.canClick / ifGrayedOut        → 签到按钮态
  displayStatus                                → 服务端枚举（实测见过 31，含义未定）
  subTitleList[].text                          → "已连续打卡5天"

实测样本（uid 492*914）：currentSignNum=5 / totalSignNum=5、couponInfo.canClick=false、 按钮文案「明日再来」、displayStatus=31、页面文案「今日券已领完」→ 结论是*今日已签满且券领完， 不是"CK 无效"。

判定顺序（以 canClick 为准，不要猜枚举）

  1. couponInfo.hasReceived → already
  2. couponInfo.canClick or signButtonInfo.canClick → ready
  3. 按钮文案含「已领完 / 明日再来」→ sold_out
  4. currentSignNum < totalSignNum → manual
  5. 其余 → window

displayStatus 只是原样带出，不参与判断——枚举值不稳，canClick 才是权威。

未登录 / 无资格怎么区分（实测）

情况 页面特征 判定
CK 有效 rawData.store 有内容且含 signCouponInfo 正常解析
CK 失效/未登录 返回 51KB 外壳，store 为空对象，无登录页文案 AUTH
已登录但无任务 store 有内容但没有 signCouponInfo INELIGIBLE

坑：失效 CK 不会跳 /login，页面 URL 和标题都正常，只靠"有没有登录框"判断会误报成 NO_RESP。

性能对比

  • 核验（HTTP GET + 解 rawData）：~700ms，容器内存无增量
  • 旧方案（起无头 Chromium 等 XHR）：~22s，且等不到数据
  • 领取（必须浏览器）：页面自己生成 anti_content 签名，不伪造

落库坑

_finish_login 只存 user_id 不存 cookie，是"接了账号什么都查不到"的根因。 现在存整串 cookie，并且取用时统一走 _ck_raw() / _ck_jar()， 同时兼容 raw 与 cookie 两种键名（数据库存 cookie，解析函数产出 raw，不归一就必然失败）。

夜间引擎：调度时序与跨日坑

时序：23:30 预检 → 00:00 领取 → 00:30 回收 → 每 5 分钟扫到期（scheduler()，20s 轮询， 用 marks[day] 去重，进程重启后 marks 清空但当日仍会重跑一次）。

bug（已修）：run_nightly() 原来只处理 snapshot.status=='ready' 的账号，而快照来自 23:30 预检。 23:30 时券通常已领完（sold_out），跨过 00:00 额度重置后快照仍是 sold_out → 整晚跳过，一张都不领。 修法：00:00 对非 ready 账号现查一次（provider.check()，约 700ms），现查为 ready 才继续领取， 并把新快照写回。沙盒验证：快照 sold_out → 现查 ready → 领取 received → 扣 1 次。

bug（已修）：global_reports 原来用 INSERT OR REPLACE 写入本轮计数，重复运行会把当天统计清零。 改为按当天 history 汇总（COUNT(DISTINCT account_id) / COUNT(DISTINCT CASE WHEN status='received' ...)），幂等。

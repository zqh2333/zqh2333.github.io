# 运维知识库自动沉淀发布（2026-10-08）

## 背景
知识库是 Hermes 的长期记忆来源。要求：**有新知识沉淀就自动发布**到公开站点，既可人工查阅，也可作为 AI skill / 记忆来源。

## 结论
建立一条**无人值守**发布链路：本地知识库 → 脱敏生成 → 泄漏复检 → 变化检测 → 推送 GitHub → 线上实测。

| 项 | 路径 / 值 |
|---|---|
| 站点 | `https://<user>.github.io/kb/` |
| 源 | `~/.hermes/knowledge-base/` |
| 生成器 | `~/.hermes/scripts/kb_publish.py` |
| 部署器 | `~/.hermes/scripts/kb_deploy.py` |
| 包装脚本 | `~/.hermes/scripts/kb_auto_publish.sh` |
| 定时 | cron `0 */6 * * *`（`no_agent=true`） |
| 构建产物 | `~/.hermes/kb-build/{work,site,repo}` |
| 凭据 | `~/.hermes/secrets/github.env`（600） |
| 变化指纹 | `~/.hermes/kb-build/.site.sha256` |

## 关键设计
1. **静默约定**：无变化 → 无输出（cron 不打扰）；发布成功 → 一行核心结果；失败 → 一行关键原因 + 非零退出。
2. **脱敏兜底**：`<LAN>` 这类"字母 x"字面量原正则漏网 → 补 `10\.10\.10\.[0-9A-Za-z]*`，并覆盖 `192.168/172.16` 私有段。
3. **Jekyll 陷阱**：GitHub Pages 跑 Jekyll 会**忽略 `_` 开头目录** → `_meta/` 输出时映射为 `meta/`（只改输出层，不动源目录）。
4. **防冲掉**：双分支推送 —— `master` 的 `/kb/`（立即生效）+ `hexo` 的 `source/kb/` + `_config.yml` 加 `skip_render: kb/**`。
5. **★数量校验**：知识库内有 `root:root 600` 文件，普通 `cp` 会**静默少复制** → 必须 `sudo cp -a` + `chown` 回属主，且**复制数量必须等于源数量**，否则中止（绝不发半份）。

## 故障与修复（真实记录）
- **症状**：首次自动运行只发布 99 篇（源 101 篇），线上少了 2 篇。
- **根因**：`index.md` 与 `runbooks/port-scan-ip-range-2026-09-29.md` 属主 `root:root` 权限 `600`，agent 无权读；`cp ... 2>/dev/null || true` 把错误**吞掉**了。
- **修复**：改用 `sudo -n cp -a` + `sudo -n chown -R`，并新增"源篇数 == 副本篇数"硬校验。
- **教训**：**静默失败比失败本身更危险** —— 任何"吞错误 + 继续"的写法都必须配一个可验证的数量/哈希断言。

## 验证（2026-10-08）
- 全站 HTTP 200：`/`、`/kb/`、`/kb/meta/SCHEMA.html`、5 个分类目录页、文章页、原始 md。
- 首页分类计数 23/30/38/7/3 = **101 篇**。
- 线上泄漏复检全 0：用户名、内网段、密钥路径、家目录、域名、公网 IP。
- 幂等性：指纹命中时 1 秒内静默退出，不重复推送。
- **Pages 构建卡死**：一次提交后构建停在 `building` 8 分钟未完成（正常约 45 秒）→ `POST /pages/builds` 触发重建后 42 秒完成。**排查手法**：对比 `pages/builds` 历史耗时，异常时手动触发重建。
